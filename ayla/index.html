Autonomous Yielding Learning Assistant
Works with GitHub

Ayla enhances AI-assisted development by coordinating execution across multiple agents and tools through GitHub.

She coordinates AIs and tools, including Grok, ChatGPT, VS Code, and Cline, using the GitHub API and repositories as a shared source of context, work, and continuity.

Her goal is to make development more organized, secure, and efficient. Instead of letting each agent work in isolation, Ayla maintains shared missions, decisions, states, and evidence to:

  • Minimize communication failures between AIs and tools.
  • Prevent duplicate work and block two local bridges from handling the same task.
  • Reduce version errors, stale context, and incorrect references.
  • Detect known failures, apply only safe corrections, and stop when risk or an unverified result is found.
  • Limit attempts and execution time to prevent tasks from becoming trapped in loops.
  • Validate results with tests, integrity records, and evidence before declaring success.
  • Work with GitHub projects from Windows and Linux environments.

These capabilities support projects of different sizes, including games, applications, and cross-platform tools.

How she talks to tools

Ayla connects AI services, GitHub, and the developer’s local environment through structured and auditable missions.

  • Grok and ChatGPT — share plans, tasks, evidence, and handoffs through the same GitHub record, allowing either one to continue the other’s work.
  • VS Code + Cline — perform assisted editing through a controlled queue; full automation of this bridge remains under development.
  • Local execution — deterministic tasks can be sent to the computer through one authorized bridge, using approved scripts, time limits, and results returned to GitHub.
  • GitHub — is IA Squad’s official source for code, state, history, evidence, and collaboration.

Governed learning

Ayla already records real outcomes, quality, corrections, and evidence. Repeated experiences can become candidates for reusable lessons, but no lesson automatically changes code, policies, or validated knowledge. Sensitive changes still require tests, sufficient confidence, and review.

Backup and restore

Before an authorized deletion, Ayla requires a verified backup, integrity testing, and a 7-day quarantine. If any verification fails, deletion is blocked. Full restoration remains part of the continuous testing and improvement program.
